## Implemented behavior

Before: `pob2opt market import` did not exist. Item text went only through `pob2opt parse`, which read PoB item text and misread game clipboard text (`Item Class:` first) as PoB text. No listing record was ever produced. The legacy harvester (`harvest.py`) queried an undocumented trade route, kept only exalted listings under a 60 exalted cap and deduplicated by name.

After:

- `pob2opt market import --input FILE --corpus DIR --catalog DIR` stores the file as a source document and writes `ItemInstance` and `Listing` records plus a `ParseResult` naming them. Item text is `access_method: local_file`; a capture file is `manual_capture`. Same bytes and catalog again report the stored result. Exit 0 imported (status may be `partial`), 2 invalid file, 3 refused format or missing catalog.
- Input formats:
  - PoB item text, through the P04 path unchanged.
  - Game clipboard text (`parsers/gametext.py`): categories from the suffix markers PoB's reader accepts (`implicit`, `enchant`, `rune`, `fractured`, `crafted`, `desecrated`; `mutated`, `unscalable`, `disabled` as line flags); requirements with level and attributes; quality, sockets, item level, `Limited to`, `Radius`, item flags and the original text. The first unmarked modifier section is `explicit`; `Grants Skill:` is `implicit`; any later unmarked line (a unique's flavour text) is kept as category `unknown`, `unresolved`, and the item is `partial`. Displayed weapon and defence totals stay in `raw_text` only, because PoB reads those lines as base values. A `Note:` price line is reported and kept out of the item. Advanced copy is refused.
  - `pob2opt.market_capture` v1 JSON (`market/capture.py`): provider label, realm, league, observation time and entries of item text plus an optional listing (listing ID, optional price `{amount, currency}`, quantity, listed time, URL). This is the user's own observation, not a provider export.
  - Provider export JSON: refused, `provider_export_blocked`, citing D01. No provider representation is approved, so none is invented.
- Item/listing split. Item identity is `item_hash` (P01 canonical stats); its record ID is `market-item/<catalog>/<item_hash>`, so equal stats are one item record whatever the display name, and different rolls under one name are two. Listing identity is `listing/<provider>/<realm>/<league>/<listing id>` (URL-quoted parts), used as both `listing_id` and record ID. Price, currency, quantity and times live only on the listing.
- Price is copied: decimal string in its original currency, any currency, no upper bound, no conversion. `price: null` or absent stays null; `"0"` is a different, kept value. A JSON number amount is refused because a float cannot carry it exactly.
- Availability: a listing from a capture is `observed` at the capture time (`last_checked_at` equals `observed_at`). An item with no listing has no listing evidence and reports `unknown` (`importer.item_availability`).
- Dedup and conflicts. Equal item hashes in one input are one record; an item already stored is reused. A listing repeated with identical content is reused. The same listing with different content in one file makes the file invalid. A listing already stored with a different observation keeps the stored record, is not written, and the import is `partial` (`listing_conflict`): replacing an observation is refresh, P05-T04.
- P04 parser `.4`: `pob2opt parse` now reads game clipboard text through the same reader. Running the P02 conversion against PoB showed three defects in `import_item`, now repaired: PoB's `Rune:` socket lines were read as modifier lines (now rune names in `properties["runes"]`, kept only when a socket names a rune, and written back by `export_item`); PoB's `{enchant}{rune}` left a stray `enchant` flag (now one rune line); a magic item's base did not resolve from its name (now PoB's longest-contained-base rule, ambiguous ties unresolved). `PARSER_VERSION` is `p04-t01.4`; reparse sources to replace `.3` records.
- Listing semantic validation: an amount without a currency (`price_without_currency`) and a negative amount (`negative_price`) are rejected.

Not changed: `harvest.py`, `policy.py` and `phases.py` stay the legacy comparison path (`architecture.md`); nothing new imports them, and the harvester's transport is already quarantined. No catalog, release or compatibility code was touched.

## Deviations and unresolved questions

- `market import` takes `--catalog DIR` (and an optional `--provider` label), as `parse` does; `interfaces.md` lists only `--input` and `--corpus`.
- New input contract: the `pob2opt.market_capture` v1 file (`market/capture.py`), D01 alternative 3 (manual capture). No record schema changed. Provider export JSON stays blocked on D01.
- Listing ID convention: `listing/<provider>/<realm>/<league>/<id>`. contracts.md requires `record_id == listing_id`, so the dedup key is the ID.
- New semantic checks on `Listing` (`price_without_currency`, `negative_price`).
- Parser `.4` and the `import_item` repairs above change P04 output for game text, rune sockets and magic items; reparse affected sources.
- Open for review: attribute requirements are identity facts PoB item text cannot carry, so an item with them exports as incomplete (reported, not silent). A reviewer may decide PoB's own base-derived requirements suffice. Likewise item identity includes modifier positions, and PoB reorders rune lines ahead of enchant lines on save, so such an item's hash changes after a PoB save; the engine test records this.
- Unique flavour text cannot be told from a modifier without a unique table in the catalog, so game-text uniques import `partial`.
