## Implemented behavior

Before: the `pob-community-v2` number existed only as a script (`scripts/p09_t01_2_community_cycle.py`) with 10 ms stepping, no coverage gate and no typed result. P06 coverage could block a build but nothing consumed it.

Now `pob2opt.combat.evaluate_flicker(xml, values, ...)`:

1. Runs `analyse` on the scoring document (Pounce disabled), applies resolutions through `CoverageLedger.resolve` (P09-T01.2's rule table; this package's implemented mana/flask/sustain rules and rotation state paths; the owner's method definitions, scoped to `pob-community-v2` and never overriding settled evidence; attribution only with an explicit reviewer acceptance), re-runs `analyse` under the resulting registry and calls `decide`.
2. Builds the 120 s timeline: an integer-microsecond event loop ordered by `(time, phase, insertion_id)`, a `RotationPolicy` interpreter over named state paths, exact mana with one flask, half-open buff and score windows, strikes credited at impact.
3. Returns a typed `FlickerEvaluation`: `eligible` with the objective filled, `blocked` with null objective and a diagnostic labelled `NOT ELIGIBLE`, `missing_inputs` or `invalid_rotation` with null objective. Every case carries the blocking gaps, registry and closure hashes, applied resolutions and ledger history.

## Reproduction

From the repository root with the locked environment: `python scripts/p07_t01_flicker_cycle.py` (offline). The live check and the engine test need a clean checkout of `ce566ea` in `external/PathOfBuilding-PoE2` or `POB2_ROOT`; they start two worker processes each.

## Adverse cases

Covered: unknown predicate paths and operators, non-`use_skill` actions without timing rules, unaffordable costs (wait, or stop when never affordable), event bound, missing engine values, a method definition meeting settled evidence, a non-scoring document. Not covered: multiple targets, target death, periodic ticks and delayed projectiles (not needed by this benchmark; the loop has the phases), weapon swaps, movement actions.

## Deviations and unresolved questions

- The rotation checks the Charged Staff buff at each decision, so it refreshes the buff before a Flicker Strike when it ran out during Whirling Assault. P09-T01.2 checked it once per cycle. Result differs by 0.8%.
- Method definitions (charges assumed, Hit and Run as PoB applies it) are recorded as `fixture_checked` rules reviewed by the owner's decision. That means the implementation is checked against the method's definition, not that the game behaves this way. They apply only under `pob-community-v2` and defer to any settled evidence.
- Implemented rules (`resource/mana-flask`, `resource/mana-sustain`) are self-validated by fixtures and await reviewer acceptance.
- Damage and time totals use `math.fsum`: Python 3.12 changed float `sum()`, which made the 3.10 and 3.12 evidence differ in the last bits.
- The flask policy and starting with full flask charges are P09-T01.2 protocol choices, unchanged.
- The P06 walker only visits weapon set 1 groups, so it does not see Pounce in the as-imported seed although PoB applies its mark. The evaluator blocks any non-scoring document explicitly; a P06 fix is a follow-up.
- Open for the seed: attribution acceptance, Way of the Stonefist, Rage, five unknown buff/damage supports, stale patch profile, config conditions, reference result.
