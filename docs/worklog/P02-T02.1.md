## Implemented behavior

Before: the only release evidence was a `summary` of the 0.5.5e notes, the
reference export came from a dirty checkout, and the catalog rows carried no
weapon restriction, readable skill types, support type expressions, costs or
support compatibility, so Flicker Strike coverage could not be stated. The
verdict was `partial` for four reasons.

Now:

- **Live patch.** 0.5.5e, unchanged since 2026-10-06, read from the official
  Early Access Patch Notes index on 2026-10-17. A new `verbatim` capture
  stores the fetched bytes of the thread's staff view. Capture format 2 adds
  `raw_file`, `raw_sha256` and `raw_media_type`; a verbatim capture without
  them, with bytes that do not hash to the record, or with an excerpt line
  absent from the bytes is refused. The bundle evidence for a verbatim
  capture is the page bytes. The old summary file is unchanged and still
  loads; for the same patch the verbatim one is chosen.
- **PoB revision.** Pin kept at `ce566ea`. Upstream has no release after
  `v0.23.1` (2026-07-28); `dev` is 16 commits ahead (to 2026-10-01) with no
  new game data export and nothing touching Flicker Strike. The 0.5.5 data
  export (`49e9392`, 2026-09-10) is already in the pin. Bumping to an
  unreleased `dev` commit would change no verdict reason. The export ran
  against a fresh clone at the pin with an empty `git status`.
- **Catalog rows.** Gem rows add `weaponRequirements`. Granted-skill rows add
  `skillTypeNames`, `weaponTypes`, `requireSkillTypes`/`addSkillTypes`/
  `excludeSkillTypes` (upstream postfix order, as names), `cannotBeSupported`,
  `supportGemsOnly`, `isTrigger`, per-level `costs`, `statSets` (label, stats,
  constant stats), and for active skills `supportedBy`: the support effects
  PoB's own `calcLib.canGrantedEffectSupportActiveSkill` accepts on the
  skill's base types. A support check that raises is listed in
  `supportCheckErrors`, never counted either way (none on this checkout).
- **Flicker Strike coverage.** `catalog/supports.py` reports what the catalog
  records for the D07 pair and returns issues instead of substitutes: a
  missing row, a second gem or granted skill sharing the name, a broken
  gem-to-effect link, a support flag, rows from an older adapter without
  `supportedBy`, or support check errors.
- **Fixtures.** Fixture set version 2 adds 14 Flicker Strike fixtures: two
  availability, eight field (ids, link, support flags, gem weapon, skill
  types, weapon types, stat sets, level 20 cost), one `members` (all 258
  accepted support effects stay accepted; Fork, Pierce I and Spell Echo stay
  rejected; a new upstream support is not a mismatch), and three behaviour
  documents saved by the clean engine (alone, with Rapid Attacks I, with
  Fork). The Fork document must equal the alone document; the Rapid Attacks
  one must differ in Speed.

version 1 capture, an excerpt not in the page, a summary still loading, the

excluded support added to `supportedBy`, an unrelated new support, a

  catalog carries no such stat or type; the game rule is unverified.
- Gameplay: none of this is gameplay evidence.

## Deviations and unresolved questions

1. **Retained gap: `catalog-predates-current-patch`** (ranking_sensitive).
   The rule compares the engine's release date (changelog `0.23.1`,
   2026-07-28) with the patch date. The pin is newer than that release and
   contains the 0.5.5 data export, and the 0.5.5b to 0.5.5e notes (stored)
   name no skill, gem or Flicker Strike change. That is not proof the
   catalog models 0.5.5e, and no PoB release exists to point at, so the rule
   was not changed and the gap stays. Needed evidence: a Path of Building
   release whose data covers 0.5.5e, or a reviewed decision that an
   unreleased commit with a dated data export may stand in for a release.
   Collection: source lookup on the upstream releases page.
2. **Retained gap: `slot-accepted-base-categories`** (blocking, from
   P02-T02). Still blocks `verified`. Needed evidence and collection method
   are unchanged in the export: the accepted base categories per slot from
   the engine's item-slot code or the game data, then a sourced rule; owner
   P02-T03.
3. **Other retained rule gaps** (not verdict reasons): quest passive point
   rewards, ascendancy point unlock schedule, weapon-set point unlock levels,
   gem level legality, skill level limit. Unchanged from P02-T02, each with
   its needed evidence in `catalog-export.json`.
4. **Resolved:** `release-evidence-not-verbatim` (verbatim capture) and
   `unpinned-checkout` (clean clone). They return if the user's dirty
   checkout is used.
5. **`ADAPTER_VERSION` bumped to `p02.2`** and the catalog hash changed
   (`e82da2ea…` to `ac0e9308…`) because rows gained fields. Entity counts are
   identical. Profiles pinned to `p02.1` are refused by `_check_profile`, as
   designed.
6. **Publication time zone.** The forum shows post times without a zone;
   0.5.5e is recorded at `01:32:07Z`, consistent with the earlier capture.
   Unverified; ordering between patches does not depend on it.
7. **The historical `docs/evidence/P02/catalog-export.json` is unchanged.**
   The slice beside it was regenerated, because the offline tests need the
   new fields and the Flicker rows.
8. **Pin not changed.** No deviation to review on the submodule.
9. Blocked: nothing.
