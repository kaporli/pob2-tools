## Implemented behavior

Two halves.

### 1. The primitive inventory

Input: a `PrimitiveSnapshot` from `EngineAdapter.primitives`, which until now
was a bag of raw PoB output keys reporting `semantics_status: "undeclared"`
and naming this task as the owner of units.

Now `pob2-optimizer/pob2opt/evaluation/primitives.py` is that declaration. It
is one table of `PrimitiveDefinition` rows: primitive id, native PoB key,
unit, owner, what the number already includes, what it excludes, status, and
the controlled fixture that settled it. `PrimitiveSnapshot` gained
`declared()`, `gaps()` and `primitive(id)`; `semantics_status` is now
`"declared"` and the snapshot carries `semantics_version` `p02-t04.1`.

The rules the module exists to keep:

* **One owner per primitive.** `owner: pob` means the pinned engine computes
  it and nothing downstream recomputes it. `owner: simulator` means P07
  computes it and the engine supplies no value at all. A test asserts no
  engine key is claimed by two primitives and every primitive sits in exactly
  one category.
* **A missing native output is a gap.** `declare()` returns
  `(declared, gaps)`; a primitive whose key is absent produces a
  `PrimitiveGap` with a `DataGap` kind, an explanation and a specific
  `needed_evidence`. `snapshot.primitive("cooldown_s")` on a skill with no
  cooldown returns `None`, never `0`, because a zero cooldown would mean an
  unbounded use rate.
* **An ambiguous unit stays unresolved.** `CombinedDPS` is damage per second
  for most skills and damage *per use* for skills whose data sets
  `showAverage` (`CalcOffence.lua` line 6265). It is declared `conditional`
  and resolved from the engine's own flag, which `buildSummary` in
  `pob2-mcp/pob2mcp/bootstrap.lua` now reports as `mainSkillShowAverage` and
  `LoadedBuild` now carries. Without the flag the primitive is a gap.

Thirteen controlled fixtures established the semantics. Each is a complete
build document differing from its pair in exactly one declared way, built by
`scripts/p02_t04_primitive_fixtures.py` and evaluated through the P02-T01
adapter. The findings, with numbers, are in
[`docs/evidence/P02/primitives.md`](../evidence/P02/primitives.md); the three
the task named explicitly:

* **Projectile overlap is not included.** Tripling `ProjectileCount` from 1 to
  3 left `AverageDamage` and `TotalDPS` bit-identical. PoB does ship per-skill
  overlap configuration variables, but every one is gated on an `ifSkill`
  naming a skill absent from the pinned PoE 2 catalog.
* **Trigger cadence is not included.** PoB models it when the skill data
  declares `triggerRate` or `triggerTime`. All five meta gems in the pinned
  catalog that can wrap a spell left the socketed Fireball scored at its own
  cast rate, to the last digit.
* **DoT duration is not included in the DoT number.** A duration support moved
  `Duration` from 5.016 s to 6.765 s and left `TotalDot`, `TotalDotDPS` and
  `CombinedDPS` unchanged. The reported figure is a rate while the effect is
  active; ailment damage over time is the exception, where PoB folds ailment
  chance and stack potential into the rate.

### 2. The F02 repair

Input: the legacy `phases.task_tier`. It computed a rotation-adjusted DPS
(enabler overhead, reload duty, gauge lockout) and then threw it away:

```python
base_dps = realistic if realistic else rot["dps"]
hon = concentration.honest(geom, base_dps)
```

`realistic` was a bare `worker.metrics()["dps"]` re-read after enemy
conditions were switched on, with no action-time correction. The reported
`honest_single_target` was four times the rotation it claimed to describe, and
halving the duty cycle again changed it not at all.

Now `pob2-optimizer/pob2opt/legacy_estimates.py` is the only place that
arithmetic happens. `sustained_estimates()` takes the rotation-adjusted number
as its only damage input, and the condition measurement enters as a ratio of
the same engine output read twice, so the unit cancels and the conditions
scale the rotation instead of replacing it. `phases.py` no longer imports
`concentration` at all, and a test asserts that, because the defect came back
once already by existing in two places.

Renaming: the legacy `floor` and `ceiling` are not bounds, they are one
measurement with every scoped condition off and one with them on. They are now
`condition_off_estimate` and `condition_on_estimate`. `floor`, `ceiling`,
`honest_single_target` and `clear_score` are written as deprecated aliases
only, and every row carries `estimate_status: legacy_heuristic_unvalidated`.

Favourable fallbacks removed:

| Was | Now |
|---|---|
| `except Exception: honest_st = realistic or rot["dps"]`, archetype `"unknown"`, which is a 1.0 multiplier | the estimate is `None` and `estimate_gaps` names the failure and its exception type |
| `concentration.single_target_mult` returning a 1.0 fudge for an unrecognised archetype | `honest()` returns `None` for both numbers outside `KNOWN_ARCHETYPES` |
| the clip-duty Lua returning `duty = 1` when a clip weapon had no reported attack rate | it returns no duty and a reason; the row records `reload_duty_unknown` and reports no sustained estimate |
| `_score = max(dps, full)`, comparing `CombinedDPS` with `FullDPS` | `legacy_estimates.screen_score` uses only the per-second number when `showAverage` says the units differ, and returns `None` when neither is present |
| the report substituting `realistic_dps or rotation_dps or 0` for a missing estimate | `cli._num` renders `unknown`, and `sort_key` ranks such rows last instead of as zero |
| `concentration.load_constants` swallowing every exception | `OSError` and `ValueError` are named and reported to stderr |

The legacy rotation model's own clamps (enabler overhead capped at 0.60, uptime
floored at 0.40) are kept, because changing them would be inventing a new
model, but they are now reported: `policy.rotation_dps` returns `assumptions`
and `saturated`, and a saturated row says so rather than presenting a number
that stopped responding as a measurement.

## Adverse cases

Exercised:

* a clip weapon whose attack rate the engine did not report: no duty, no
  sustained estimate, a named gap, and the gauge composition skipped rather
  than multiplying `None`;
* a worker whose engine cannot answer `OPT_geometry`: no single-target or
  clear estimate, archetype `None`, the exception type recorded in the gap;
* an unmeasurable condition uplift (a zero bare reading): the condition-on
  number is `None` while the condition-off one survives;
* an unrecognised delivery archetype: both multipliers `None` instead of 1.0;
* a snapshot from a synthetic worker that emits no PoB key at all: every
  declared primitive is a gap and `declared()` is empty;
* `CombinedDPS` present with no `showAverage` flag: not supplied;
* a skill with no cooldown, and one with a cooldown: gap and declared value;
* a rotation whose setup time exceeds the legacy clamp: `rotation_saturated`
  true and the clamp named in the row.

  `FixtureBuilder.__init__` at `Pob2Engine.__init__`, taking all 18 tests with

## Deviations and unresolved questions

1. **`LoadedBuild` gained two fields.** `main_skill_show_average` and
   `main_skill`. Both are additive and defaulted; the first is required to
   give `CombinedDPS` a unit at all. `buildSummary` in the MCP bootstrap
   reports them, which changes that handler's output for every caller.
2. **The legacy rotation clamps were kept.** Enabler overhead capped at 0.60
   and uptime floored at 0.40 are properties of the first-order legacy model,
   not measurements. Removing them would be designing a replacement model,
   which is P07's. They are now reported through `assumptions` and
   `saturated`, so the acceptance fixture demonstrates monotonic response
   below the clamp and the row says when the clamp bound. Flag it if the
   reviewer reads a saturating estimate as failing "increasing setup time
   reduces sustained performance".
3. **`screen_score` changed what the legacy screen ranks on.** When PoB flags
   a skill `showAverage`, `max(CombinedDPS, FullDPS)` was comparing damage per
   use with damage per second; the per-use number is now ignored. This changes
   legacy screen ordering for those skills. It is a unit repair, not a scope
   change, but it does mean a legacy run's output is not comparable across
   this commit.
4. **Trigger cadence is a data finding, not a game rule.** F-TRIG shows the
   pinned catalog declares no trigger rate. Whether PoE 2 meta gems have one
   is a sourced-evidence question and belongs to P06; the gap records what is
   needed.
5. **The running checkout is not pinned.** Unchanged from P02-T01: the
   configured PoB checkout has untracked files in `src/`, so `is_pinned` is
   false and the dirty hash is on every recorded value.
6. **Blocked: nothing.** The submodule is still absent and was deliberately
   not restored.
