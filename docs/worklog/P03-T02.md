## Implemented behavior

Input: a saved file, a PoB build code, or a URL. Output: a `SourceDocument`
describing the stored original bytes and an `AcquisitionResult` describing the
attempt, both written through the P01 `RunStore`. There was no acquisition code
before this; `pob2opt.catalog.evidence` built `SourceDocument` records for the
engine's own evidence bundle, and nothing else produced either record.

**Local acquisition.** `AcquisitionService.ingest_file`, `ingest_build_code`,
`ingest_bytes` and `ingest_url` all funnel into one write path. The payload is
identified (explicit kind, else media type, else file extension, else content
sniffing) and checked. XML must be well formed and free of doctype and entity
declarations. JSON must parse, and `NaN`/`Infinity` are refused as contracts.md
requires. A build code must base64-decode, inflate within the 20 MiB cap and
contain safe XML; the record stores the code as supplied, not the expansion,
because P04 owns normalization and two copies of one build would make the raw
record ambiguous. HTML is stored byte for byte and never parsed.

What it refuses: an unreadable file (`not_found`), a payload over the size
limit, malformed JSON or XML, an unsafe XML construct, a corrupt or truncated
build code and a build code that expands past the cap (all `invalid_response`),
and a payload whose kind cannot be determined (`unsupported_access`). Every
refusal writes an `AcquisitionResult` with a null `source_document_id` and no
blob. There is no code path from a refusal to a stored document.

**Idempotency.** A document's `record_id` is a UUID5 over provider, access
method, blob hash, redacted URL and external ID. Acquisition time is
deliberately excluded, so the same bytes from the same place are the same
record: the second ingestion writes no row and no blob and reports
`created=False`. The attempt is still recorded, because attempts are events and
contracts.md keeps failed and repeated ones visible.

**The HTTP layer.** `HttpAcquirer` holds all of it and knows nothing about any
provider. Host policy is an allow list (`HostPolicy.deny_all()` by default) and
is re-applied to every redirect target, so an approved host cannot hand
acquisition to an unapproved one. Timeouts are 10 s connect and 30 s read, the
size limit is 20 MiB, and at most three attempts are made for a classified
transient failure. A provider's own limits can only tighten these
(`Limits.tightened_by` takes the minimum of each bound and the maximum of the
pacing interval). Statuses map to the contracts.md vocabulary: 401/403/451 →
`access_blocked`, 404/410 → `not_found`, 429 → `rate_limited`, 408/425 →
`timeout`, 5xx and anything unexpected → `invalid_response`. Conditional
requests are sent whenever a validator is known, and a 304 is a success that
downloads and stores nothing. An advertised `Retry-After` is never shortened: a
delay within `max_inline_wait_s` (30 s) is waited out in full, and a longer one
stops the attempt and returns a `Deferral` carrying the whole delay and the
earliest time to retry.

**Credentials.** The request keeps whatever the caller supplied; everything we
store or print is redacted. A URL loses its userinfo and fragment and every
query value whose parameter name is not on a small allow list. Header values
never leave the HTTP layer. Diagnostics are assembled from redacted parts and
bounded in length, so a response body cannot be smuggled into a record.

**What it does not do.** No provider adapter, no pagination, no field
extraction, no guide parsing (P03-T03 and P03-T04). Nothing acquired is ever
executed: the package contains no `eval`, `exec`, `compile`, `subprocess`,
`pickle` or `marshal`, and a test asserts that on the syntax tree. Nothing here
imports the engine, so acquisition runs with no PoB checkout at all.

## Reproduction

Working directory: the repository root. Prerequisites: the dev install from
`tests/MANIFEST.md`. No PoB checkout, no credentials and no network are needed
for anything in this section.

```
python -m pytest tests/unit/test_p03_t02_local.py tests/unit/test_p03_t02_http.py -q
python -m pytest tests/unit -q
python -m pytest -q
python -m pytest -m network -q
python scripts/generate_schemas.py --check
python scripts/p03_t02_evidence.py
```

End to end, with a file of your own:

```
python -m pob2opt.cli ingest --provider local --input my-build.xml --corpus C:\tmp\corpus
python -m pob2opt.cli ingest --provider local --input my-build.xml --corpus C:\tmp\corpus
```

The first prints `"created": true` and a blob hash; the second prints the same
`source_document_id` with `"created": false`. Exit `0` both times. A URL
without `--allow-host` exits `3` and sends nothing. No command here needs PoB
or live credentials, and none of them should ever be given a token on the
command line: pass one as a request header through the Python API instead, and
it will be redacted out of everything that is stored.

## Adverse cases

Exercised: an unreadable and a missing file; a payload over the size limit as a
local file, as a declared `Content-Length` and as a stream that only reveals its
size while being read; malformed JSON, `NaN` in JSON, malformed XML, a doctype
and an entity declaration, XML nested past the depth cap; a build code that is
not base64, is not a deflate stream, is truncated, or expands past the cap
(checked at both the shipped 20 MiB default and a small injected cap); 403, 404,
429, 408, 503, an unexpected 418, an empty 200 and a 304 with no validator; a
connection failure; a transport timeout; a redirect to an unapproved host, a
redirect with no `Location` and a redirect loop; a URL carrying userinfo; plain
`http`; a bare IP literal; an unapproved port; a path outside an approved
prefix; a provider trying to loosen every limit; and a token in both a query
string and a request header.

Not tested, and deliberately so: anything that would contact a real provider.
There is no provider to contact until P03-T01 chooses one, and no test here
opens a socket. The `RequestsTransport` class is therefore the one piece of this
change that no test executes; it is a thin wrapper that converts `requests`
exceptions into `TransportTimeout` and `TransportConnectionError` and streams
`iter_content`, and it holds no policy. Also untested: concurrent ingestion of
the same bytes from two processes. The blob store is atomic and the document
identity is deterministic, so the expected outcome is one row and one blob, but
that is reasoning, not a measurement.

## Deviations and unresolved questions

1. **The host allow list ships empty.** interfaces.md says to follow only
   approved hosts; P03-T01 has not approved any. A URL therefore fails with
   `unsupported_access` until a manifest exists. `pob2opt ingest --allow-host
   HOST` lets an operator approve one host for one invocation, which is the only
   way to exercise the path before P03-T03. It is explicit, per invocation, and
   still subject to https, no-userinfo and redirect re-checking. Flagging it
   because it is a human override of a policy gate.
2. **A failed `AcquisitionResult` cites itself as its own provenance.**
   `validation._provenance_errors` requires every persisted record to name at
   least one provenance ID, and a failed attempt produced nothing to name. The
   alternatives were to invent a document for a failure, which is exactly what
   this task forbids, or to widen the rule. A successful attempt and its
   document cite each other, the same pair `pob2opt.catalog.evidence` uses.
   If the reviewer prefers an explicit "acquisition request" root record, that
   is a schema addition and a decision for P01's owner.
3. **`source_manifest_id` for local input is the literal `local-input`.** The
   field is required and non-nullable, and local input has no capability
   manifest. `--manifest-id` overrides it once manifests exist.
4. **`max_inline_wait_s = 30 s` is a new constant.** interfaces.md fixes the
   timeouts, the size limit and the attempt count, but does not say how long a
   process may block on an advertised delay. Thirty seconds is the read timeout,
   chosen so that waiting never exceeds the longest wait the same request could
   already incur. Anything longer is scheduled, with the full delay preserved.
5. **A redirect does not consume an attempt**, it consumes a redirect
   (`max_redirects = 3`, a new constant for the same reason). The three attempts
   in interfaces.md are for classified transient failures, and a redirect is
   not one.
6. No schema change was required; `generate_schemas.py --check` still passes.

Unresolved and blocking nothing here: which providers will be approved, what
their real rate limits are, and whether any of them supports `ETag` or
`Last-Modified`. All three are P03-T01 findings. The conditional-request path is
implemented and tested, but whether any provider will exercise it is unknown.
