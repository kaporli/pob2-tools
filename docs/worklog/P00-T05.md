The CI lane deliberately checks out **without** submodules so the offline suite
has to stand on its own, and it contains a step whose only job is to fail if the
engine tests ever appear to have run without a runtime:

```
if grep -qE "[0-9]+ (passed|failed)" engine.txt; then
  echo "engine tests ran without a runtime; the skip guard is broken"; exit 1
fi
if ! grep -qE "[0-9]+ skipped" engine.txt; then
  echo "no engine test was collected at all"; exit 1
fi
```

The job summary states in plain text that the engine lane is not provisioned,
why, and how engine evidence is produced instead.

## Adverse cases

- Engine runtime absent: the dedicated CI step fails the build if the engine
  tests report passes or if nothing was collected at all.
- A credential present in the environment: `doctor` reports a boolean; the
  `doctor.json` artifact is uploaded, and
  `tests/unit/test_doctor_checks.py::test_configured_credentials_are_reported_as_booleans_only`
  is what keeps that artifact safe to publish.
- `doctor` exiting 3 in CI: handled explicitly - 0 and 3 pass, anything else
  fails.
- **Untested**: the workflow on a real runner, including whether
  `pip install -e` of both packages succeeds on a clean `windows-latest` image
  and whether `tests/unit/test_import_provenance.py` passes there.

## Deviations and unresolved questions

1. **The CI workflow has never run.** It is committed but unexecuted: this
   repository is private and no Actions run was triggered as part of this task.
   The criterion is therefore *unexecuted*, not passed, and the local equivalents
   are offered in its place. First push to `main` or any pull request will
   exercise it; the likely first failure is the editable install step on a clean
   runner.
2. **`runs-on: windows-latest` is a choice, not a requirement.** The offline
   suite has no Windows-specific code except `_pe_machine` (which degrades to
   `unknown` elsewhere) and the memory probe in `scripts/measure_engine.py`
   (not a test). Windows was chosen so the lane matches the only platform the
   engine runs on. A Linux lane would be cheaper and would additionally prove
   the offline suite is portable. Reviewer call.
3. **No Python version matrix.** Only 3.12 is exercised, matching the
   development machine. `architecture.md` asks for 3.10 compatibility; adding
   `3.10` to the matrix is the cheapest way to make that claim true, and this
   task does not make it.
4. **`docs/reviews/` contains only a README.** Verdicts are the reviewer's to
   write; the engineer must not pre-fill them.
