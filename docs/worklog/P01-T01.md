## Implemented behavior

Input: nothing existed. `pob2opt` had no record layer, so every component would have invented its own dictionary shape.

Resulting behavior: the 20 record kinds of [contracts.md](../specs/contracts.md) exist as frozen dataclasses in `pob2opt/domain/`, each with a generated JSON Schema in `pob2opt/schemas/v1/`, and `validate_record` runs four passes over any of them.

### The four passes

`validate_record(record_or_dict, kind=..., index=...)` returns a `ValidationReport`; it never raises on bad data.

1. **version** - `schema_version` not in `(1,)` is rejected with a message naming the supported versions, before any schema runs, so the error says "unsupported schema_version 2; this build supports 1" instead of an enum mismatch.
2. **schema** - the generated JSON Schema for that kind. `best_match` descends into `anyOf` branches, so a nullable nested record reports `/target_entities/0/position/unit`, not `/target_entities/0/position`.
3. **shape** - decoding into the dataclass. Catches unknown fields and type confusions the schema cannot, and raises `NotANumber` for NaN or Infinity, which satisfies `{"type": "number"}`.
4. **semantic** - the record's own meaning plus cross-record references against a `RecordIndex`.

Every error carries `code`, `field_path` (a JSON Pointer), `message` and `phase`.

### Unknown, absent, zero and false

`pob2opt/domain/absent.py` makes these four states distinct:

| State | Python | JSON |
|---|---|---|
| unknown | `None` | `null` |
| absent | `ABSENT` | key omitted |
| zero | `0` | `0` |
| false | `False` | `false` |

`ABSENT` raises `TypeError` on `bool()`. `if x:` is exactly the confusion the module exists to prevent, so the comparison must be written `x is ABSENT`.

### Schemas are generated, not hand-maintained

`pob2opt/domain/schema_gen.py` builds each schema from the dataclass annotations, merging in the keywords an annotation cannot express: SHA-256 and RFC 3339 patterns, non-negative durations and counts, the decimal-string price pattern, and a small per-field `OVERRIDES` table. `scripts/generate_schemas.py` writes the files; `--check` fails if they are stale. Adding a record field is therefore automatically a schema change, as contracts.md requires, and the dataclass and the schema cannot drift.

Two things JSON Schema cannot express stay in the semantic pass: NaN/Infinity, and every cross-record reference.

### Semantic rules that encode a specification sentence

| Rule | Code | Where contracts/interfaces says it |
|---|---|---|
| A failed acquisition carries no SourceDocument | `fabricated_source_document` | contracts.md, SourceDocument |
| A persisted record traces back to something | `missing_provenance` | contracts.md, common conventions |
| `record_id` equals the record's own domain ID | `identity_mismatch` | the two identities cannot drift |
| No passive allocated twice | `duplicate_allocation` | contracts.md, hashing |
| Original payload preserved on every build | `missing_raw_payload` | "metadata-only import never masquerades as a reconstructed build" |
| `needed_evidence` names a measurement | `vacuous_evidence_request` | "Need more data is not acceptable" |
| A null metric requires a gap | `unexplained_missing_metric` | "Metrics absent from the implementation are null with gaps" |
| A screen result has no completion time | `screen_cannot_time_an_encounter` | "A calculation of peak DPS cannot populate completion time" |
| An unresolved category score nulls the aggregate | `fabricated_balanced_score` | scenarios.md, missing results |
| `theoretical` mode is refused | `mode_disabled` | interfaces.md, "disable it until those rules are present" |
| An empty item pool is unresolved input | `unresolved_item_pool` | interfaces.md, request file |
| A manifest has resolved `workers` and patch | `unresolved_workers`, `unresolved_patch` | interfaces.md, request file |
| One owner per mechanic | `ambiguous_mechanic_owner` | contracts.md, MechanicRule |

`MeasurementMethod` has four values and none of them is PoB output, a guide claim or a ladder entry, so `observation.measurement_method: "pob_calculation"` fails the schema. That is contracts.md's "PoB outputs, guide claims and ladder level are not independent gameplay observations" expressed where it cannot be worked around.

## Deviations and unresolved questions

1. **Schema location.** contracts.md says `schemas/v1/`. The files are at `pob2-optimizer/pob2opt/schemas/v1/` so a record can be validated from an installed wheel, not only from a source checkout (confirmed: the built wheel contains all 20). The path relative to the package is exactly `schemas/v1/`.
2. **`jsonschema` is now a runtime dependency** of `pob2-optimizer`, not a test-only one, and is declared in its `pyproject.toml`. It was already pinned in `requirements-dev.txt` and both locks, so no lock changed.
3. **`catalog_hash` is excluded from `item_hash`.** Reasoning is in the `identity.py` module docstring and belongs to P01-T02; it is noted here because the item record carries both fields.
4. **`MeasurementMethod` and `TrialOutcome` are new closed vocabularies** that contracts.md describes in prose rather than listing. `Observation.outcome` and `Observation.censoring_reason` are likewise new fields, added so that "store failed and censored trials" is representable. If the reviewer wants these as free text instead, that is a contract change and a migration test.
5. **`PredicateOperator` is fixed at nine operators in v1.** contracts.md assigns the finite predicate vocabulary to P07. Extending it is a schema change plus a migration test, which is the behaviour contracts.md asks for; it is called out so P07 is not surprised.
6. `Listing.quantity` is nullable and documented as "unknown may not be read as more than one". contracts.md mentions quantity only in prose.

No decision record is requested: none of the above is a game-rule interpretation or a threshold change.
