## Implemented behavior

Input: `pob2opt doctor --json` from `docs/specs/interfaces.md`, which did not
exist. Previous behavior: a broken environment surfaced as a `ctypes` `OSError`
or a silently wrong import. Resulting behavior: nine named checks, a structured
JSON report on stdout, prose on stderr, and exit `0` / `2` / `3` per the
interface spec.

| File | Why |
|---|---|
| `pob2-optimizer/pob2opt/doctor.py` | The diagnostic. Each check is a pure function of explicitly passed inputs so fixtures can build each failure mode. |
| `pob2-optimizer/pob2opt/cli.py` | `main(argv=None)` dispatches `NEW_COMMANDS` before building the legacy phase parser, and returns an exit code. |
| `tests/unit/test_doctor_checks.py` | The acceptance scenarios. |

Checks and what each blocks:

| Check | Blocking | Blocks when not ok |
|---|---|---|
| `python_runtime` | yes | `offline_pipeline` (below 3.10) or `engine` (not 64-bit) |
| `packages` | yes | `offline_pipeline` |
| `package_provenance` | yes | `reproducible_runs` |
| `pob_directory` | yes | `engine` |
| `pob_runtime_dll` | yes | `engine` |
| `pob_profile` | yes | `engine` |
| `pob_catalog` | yes | `engine`, `catalog_export` |
| `providers` | **no** | `live_market` (informational only) |
| `run_location` | yes | `runs` |

Design notes a reviewer should check:

* `_pe_machine` reads the PE COFF header of `lua51.dll` to report `x86`/`x64`
  and catch a bitness mismatch *before* `ctypes` fails opaquely. It reads a few
  bytes; it never loads the library.
* `package_provenance` exists because of the P00-T01 finding: both packages were
  installed editable from pre-monorepo checkouts.
* `pob_profile` reports layout markers and version evidence and explicitly
  records `patch_profile_approved: false` with `patch_profile_owner: "P02-T02"`.
  Layout evidence is not a patch approval, and the JSON says so.
* `run_location` probes the nearest *existing* ancestor, so the diagnostic never
  creates the run directory as a side effect.
* `doctor` is dispatched before the legacy parser is built, so it cannot inherit
  the legacy `--level`/`--out` requirements or reach `PHASES`.

## Reproduction

```

python -m pob2opt.cli doctor --json               # JSON stdout, prose stderr
python -m pob2opt.cli doctor --json --pob-root C:\nonexistent   # exit 3
python -m pytest tests/unit/test_doctor_checks.py -q            # 13 passed
```

`pob2opt doctor --json` works identically once the console script is installed
from this working tree.

## Adverse cases

Exercised: missing PoB directory; existing directory with no DLL; directory
missing a required layout entry; 32-bit DLL under 64-bit Python; packages
importable from outside the repository; a configured `POESESSID` and an existing
token file (reported as booleans, values never serialized); a run root whose
parent exists but whose own directory does not; an unknown command-line option;
a working directory containing spaces.

Not exercised: a read-only run location on Windows (`os.access(..., W_OK)` is
unreliable there for ACL-only denials, so the `incompatible` branch of
`check_run_location` has no test); a non-Windows host (`_pe_machine` would
return `unknown` for a `.so`); Python below 3.10 (none installed, so the
`INCOMPATIBLE` branch of `check_python_runtime` is untested).

## Deviations and unresolved questions

1. **"Incompatible profile" is interpreted as checkout layout, not a patch
   profile.** `interfaces.md` mentions a `catalog_profile`, but that contract is
   owned by P02-T02 and does not exist yet. `check_pob_profile` therefore
   reports layout markers plus version evidence and sets
   `patch_profile_approved: false`. If the reviewer wants `doctor` to validate a
   `--profile FILE` once P02-T02 lands, that is an additive change to the same
   check.
2. **`providers` is non-blocking and reports status `unknown`.** Making it
   blocking would make exit 3 permanent for every offline run, which contradicts
   "allow an explicitly offline run". Flagged because it is a status-semantics
   choice.
3. Two `check_*` branches are untestable on this host (see Adverse cases).
4. `cli.main()` now returns an exit code and `__main__` uses `sys.exit(main())`.
   The legacy phase path is otherwise untouched and still returns `0` on
   success; previously it returned `None`, which also meant exit 0.
