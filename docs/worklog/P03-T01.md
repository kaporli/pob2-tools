## Reproduction

Working directory: repository root. Prerequisites: the dev install from `tests/MANIFEST.md`. No PoB, no network, no credentials.

```
python -m pytest tests/unit/test_p03_t01_capabilities.py tests/unit/test_p03_t01_source_inspect.py -q
python -m pytest tests/unit -q
python scripts/generate_schemas.py --check
python -m pob2opt.cli source inspect --provider mobalytics --out runs/p03-inspect
python -m pob2opt.cli source inspect --provider maxroll --out runs/p03-inspect
python -m pob2opt.cli source inspect --provider poe-ninja --out runs/p03-inspect
```

Expected: the three inspect calls exit 0 and print a report to stdout with status prose on stderr. Mobalytics reports `access_blocked`, the other two `unsupported_access`, each with `supported surfaces: none` and `0 of 5` categories inspected. `--provider poe-vault` exits 3. A manifest that fails the structure exits 4.

In a git worktree rather than the main checkout, prepend the worktree's package directory, because `pob2opt` is installed editable from elsewhere:

```
# PowerShell
$env:PYTHONPATH = "<worktree>\pob2-optimizer"
```

The bounded inspection itself has no command. It was a one-off manual study and is recorded, not re-run. Every request it made is listed in the `evidence` array of the manifest it supports, with its URL, date and outcome, so a reviewer can repeat any single one by hand.

## Adverse cases

Exercised. An unknown provider name: exit 3 with the known names, nothing written. A missing manifest directory: exit 3. A manifest missing a support flag: exit 4 naming the flag, never a pass. A manifest claiming `supported` without `confirmed`: rejected. A dropped category, a substituted category, an uninspected category with no reason: each rejected. An evidence reference that resolves to nothing: rejected. An access method or acquisition status outside the contract: rejected. An applied limit looser than the `interfaces.md` default: rejected. A manifest with neither a reproducible example nor a blocked case: rejected. The subcommand called as anything but `inspect`: exit 2. A credential-shaped string anywhere in an evidence file: the suite fails.

Observed during the study rather than simulated. HTTP 403 on six Mobalytics paths. HTTP 404 for a `robots.txt` that does not exist. HTTP 200 carrying a page shell with no records, which is the case that would become a successful empty build if an adapter trusted the status. A host the fetch tool would not reach at all.

Untested and stated plainly. Nothing here exercises an acquisition path, because there is no permitted one to exercise. Timeout, size-cap, retry and conditional-request behavior are P03-T02 and are not touched. Whether a browser-equivalent client would reach Mobalytics is untested on purpose; see the open sub-question in D02. Whether any provider's behavior changes tomorrow is not something a committed manifest can know, which is why each one carries its inspection date and the client that saw it.

## Artifacts and provenance

All three manifests are `independently_observed_external`: one client's observations of a third-party website on one date. They are not synthetic, not PoB-derived and not gameplay measurements. Each claim carries an evidence ID whose entry names the method as `direct_fetch`, `search_index` or `prior_inspection`, so an observation made by a search engine is never mistaken for one made against the provider.

- `docs/evidence/P03/mobalytics-capabilities.json`, ten evidence entries, seven of them direct fetches
- `docs/evidence/P03/maxroll-capabilities.json`, four entries, one direct fetch to the provider
- `docs/evidence/P03/poe-ninja-capabilities.json`, ten entries, nine direct fetches, one of which is the study's only reproducible acquisition
- `docs/decisions/D02-source-capabilities.md`

No third-party content is stored. The only provider payload reproduced anywhere is the six-object league list from poe.ninja's documented economy endpoint, which is a list of league names and is the evidence for the one acquisition that worked. Quoted robots and API-reference sentences are quoted as terms, kept short, and attributed. Guide text, build files, item data and passive trees are absent from this repository, and the manifests say where they would come from rather than carrying them.
