## Implemented behavior

Input: a P01 `BuildSpec`, an `EngineState`, a `PatchProfile`, and either the
build's stored original document or an explicit `BuildDocument`.

Previously there was no engine boundary at all. `pob2opt.engine_worker.Worker`
constructed `pob2mcp.engine.Pob2Engine` in whatever process imported it, changed
that process's working directory permanently, had no teardown, no request bound
and no failure classification, and cleared every imported character during
construction. `pob2opt.evaluation` did not exist.

Now:

* `EngineAdapter` is the coordinator half. It resolves every path before the
  spawn, owns one worker process at a time, bounds every request, records the
  parent working directory and raises `internal_error` if it ever moves, and
  replaces the process (never resets it) after a timeout or a death.
* `worker_main` is the spawn entry point. A worker owns exactly one Lua state
  and may relocate its own directory, which is what PoB requires. The session
  factory is injectable, so the offline tests drive the real adapter against a
  synthetic session with no PoB involved.
* `load_exact_build` and `create_blank_build` are separate operations. Only the
  second calls `OPT_setup`, and an exact load that reported otherwise is
  rejected as an internal error rather than returning a cleared build
  (research F11).
* Failures are typed: `invalid_input`, `unsupported`, `timeout`, `engine_crash`,
  `internal_error`, each mapping to one `ResultStatus` and convertible to a
  storable `ErrorDetail`. Diagnostics are redacted of absolute paths. There is
  no `except: pass` on the boundary.
* A `PatchProfile` pinning a different PoB commit than the running checkout is
  refused before anything is evaluated.
* A `PrimitiveSnapshot` reports `semantics_status: "undeclared"` and names
  P02-T04 as the owner, so no caller can read a raw PoB field as a defined
  primitive with known units.

## Adverse cases

Exercised:

* a worker that never answers: typed `timeout`, process terminated, the probe
  bounded by an outer supervisor that kills the tree if the bound fails;
* a worker that leaves without answering: typed `engine_crash` naming the exit
  code; the next request runs in a new process;
* a worker killed from outside between requests: the death is reported as
  `engine_crash` on the next request rather than being silently restarted, and
  the request after that succeeds in a new process;
* a worker that cannot start: typed `internal_error` carrying the startup
  message, not a hang;
* a worker that relocates its own working directory: the parent does not move;
* a malformed build document: typed `invalid_input` naming the XML fault, and
  the worker is discarded because the engine state after a failed load is not
  reusable;
* an empty build document; a document belonging to another build; a BuildSpec
  with no raw blob; a missing blob; a blob that is not UTF-8;
* a PatchProfile pinning a different commit; an unknown commit and a modified
  working tree under `require_pinned_checkout`;
* an unknown operation: typed `unsupported`, and the worker stays alive;
* a missing checkout and a missing helper script: refused before any spawn.

Not tested:

* a real native crash of the PoB Lua state. The engine-lane case kills the
  worker from outside, which exercises the same parent-side path, but it is not
  proof that a segfault inside LuaJIT behaves identically. Recorded as a residual
  limit, not as covered.
* concurrent adapters and more than one worker at a time. The adapter owns one
  process; pool behaviour and cancellation are P08.
* `lua_close` was added and runs on every clean shutdown, but no test asserts
  that the native allocation is actually freed; only that a closed engine
  refuses calls.
* non-Windows process-tree cleanup. `kill_process_tree` has a POSIX branch that
  this environment never executes.

## Deviations and unresolved questions

1. **`EngineAdapter.primitives` returns raw engine outputs with no declared
   units.** `interfaces.md` specifies "per-action primitive values with units,
   provenance and semantic ownership". Provenance and ownership are present;
   units are not, because the inventory is P02-T04's deliverable and inventing
   it here would be the exact failure that task exists to prevent. The snapshot
   says `semantics_status: "undeclared"` so the gap is visible at the call site,
   and the return type can carry units without changing its shape. No decision
   record is proposed; flag it if the reviewer reads this as a contract change.
2. **The running checkout is not pinned.** `is_pinned` is false because the
   configured PoB checkout has untracked files in `src/`. `require_pinned_checkout`
   exists and defaults to false, so T01 records the condition rather than
   blocking on it. Whether a modified tree may produce accepted results is a
   P02-T02 decision; the dirty hash is already in the identity either way.
3. **The dirty hash covers the `git status` listing, not file contents.** It
   detects that the tree is not the pinned commit; it does not identify what
   changed. P02-T02 owns content-level hashing, and the docstring says so.
4. **`load_build_xml` now raises.** This changes the MCP server's behaviour for
   malformed input as well, which is the intended repair of P00-OBS-01. No
   caller in this repository depended on the previous silent default character.
5. **Blocked: nothing.** The submodule is still absent and was deliberately not
   restored; `POB2_ROOT` covers the engine lane, as P00 recorded.
