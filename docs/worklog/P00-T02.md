## Implemented behavior

Input: a repository with one test file, `pob2-mcp/test_engine.py`, which booted
PoB at module import, inserted a hardcoded machine path on `sys.path`, printed
results and always exited 0. Previous behavior: nothing could fail, and merely
collecting it loaded the engine. Resulting behavior: a four-directory pytest
tree with markers, a default selection that excludes network and long runs,
offline-by-construction unit tests, and synthetic fixtures with a provenance
manifest.

| File | Why |
|---|---|
| `pytest.ini` | Markers `engine`/`network`/`longrun`, `testpaths`, `--strict-markers`, and the default `-m "not network and not longrun"`. |
| `tests/conftest.py` | Prepends the monorepo package directories to `sys.path`; resolves the PoB checkout; owns the session `engine` fixture and its skip reason; restores the working directory on teardown. |
| `tests/unit/conftest.py` | Blocks outbound sockets for every unit test. |
| `tests/engine/conftest.py` | `engine` marker for the directory, `blank_build` and `opt_helpers_source` fixtures. |
| `tests/testdoubles.py` | `FakeWorker`, the synthetic double for `engine_worker.Worker`. |
| `tests/engine_helpers.py` | Shared engine-test constants and counters (a conftest cannot be imported by name). |
| `tests/fixtures/**` | Four synthetic fixtures plus `manifest.json`. |
| `tests/MANIFEST.md` | Commands, prerequisites and per-file coverage (shared with P00-T05). |
| `tests/engine/test_engine_smoke.py` | The converted smoke script, now assertion-based and portable. |
| `pob2-mcp/test_engine.py` | **Deleted**; replaced by the above. |

Fixtures created, all labelled synthetic in the file itself and in the manifest:

| Fixture | Purpose |
|---|---|
| `builds/malformed_build.xml` | Truncated, invalid PoB2 build document. |
| `builds/zero_dps_huntress.xml` | Valid Huntress with no skills: full DPS is a legitimate zero. |
| `search/two_choice_synergy.json` | Two-axis space whose optimum needs a coordinated change. |
| `combat/tiny_sequence.json` | Three-action sequence with a hand-computed DPS oracle. |
| `trade/item_all_mod_categories.json` | Trade-shaped item carrying every modifier array the converter normalizes. |

Two fixture details were corrected against the real engine rather than left as
assumptions:

* the first draft used `classId="7"`, which loads as **Sorceress**; Huntress is
  `classId="8"`. Fixed and verified by `test_engine_build_inputs.py`.
* "legitimate zero DPS" was redefined after measurement: a skill-less build has
  `FullDPS == 0` but a small non-zero `TotalDPS` from the unarmed default. The
  fixture now says exactly that, and a test pins the distinction.

## Reproduction

```
python -m pip install -r requirements-dev.txt
python -m pip install -e ./pob2-mcp -e ./pob2-optimizer
python -m pytest tests/unit                 # offline, no PoB
python -m pytest tests/integration          # needs luajit on PATH, else skips
set POB2_ROOT=C:\Users\Elias\PycharmProjects\PathOfBuilding-PoE2
python -m pytest -m engine -ra              # needs the PoB runtime
```

Expected console noise during engine runs is documented in `tests/MANIFEST.md`:
PoB's own startup output, and one `Windows fatal exception: code 0xe24c4a02`
banner per engine boot (LuaJIT's internal SEH unwinding, caught; `faulthandler`
is left enabled on purpose so a genuine native crash stays visible).

## Adverse cases

- Engine absent: 34 explicit skips with an actionable reason. Verified.
- `luajit` absent: `tests/integration` skips with a reason. Verified by running
  the group with a `PATH` that omits the LuaJIT directory: `6 skipped`.
- A unit test attempting a network connection: `tests/unit/conftest.py` raises
  `NetworkAccessDenied` from `socket.connect`, `connect_ex` and
  `create_connection`. The guard is in-process only; subprocess tests are
  unaffected and are all local `python -m ...` invocations.
- A test module placed outside `tests/`: fails `test_no_test_module_lives_outside_the_tests_tree`.
- A fixture edited without updating the manifest: fails the SHA-256 check.
- **Untested**: parallel execution (`pytest-xdist` is not installed), and a second
  concurrent engine in the same process.

## Artifacts and provenance

Everything under `tests/fixtures/` is synthetic and says so. `manifest.json`
carries SHA-256, byte count, purpose, consumers and a caveat per file, and
`tests/unit/test_fixture_manifest.py` fails if any of that drifts. No PoB output
and no provider response is checked in.

## Deviations and unresolved questions

1. **`engine` stays in the default selection.** The task says the default
   invocation excludes network and long runs; it does not say to exclude engine.
   Leaving it selected is deliberate so engine absence appears as an explicit
   skip rather than silently vanishing. Flagging it because it is a judgement
   call about the default command.
2. **`tests/testdoubles.py` and `tests/engine_helpers.py` sit at `tests/` root**
   and are imported by bare name (`tests/` is added to `sys.path` by the root
   conftest). A conftest cannot be imported by name under
   `--import-mode=importlib`, and these are shared helpers rather than fixtures.
3. The two subprocess-based unit tests (`test_collection_is_offline.py` and the
   CLI half of `test_doctor_checks.py`) spawn `python`. They are local and
   offline, but they are not covered by the in-process socket guard.
