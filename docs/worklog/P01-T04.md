## Implemented behavior

Input: identities from P01-T02 and a store from P01-T03. The behaviour being replaced is P00 finding F05: the legacy cache was keyed by bare filename, so a `gems.json` produced for one level, league, budget or PoB revision was served to any other request.

Resulting behavior:

### The key lists every dependency once

`EvaluationKey` in `pob2opt/domain/cache.py` has one field per dependency in architecture.md, so adding a dependency is one edit and an immediate test failure wherever it was forgotten. `DEPENDENCY_FIELDS` maps the nine names the acceptance case uses onto those fields, and `test_every_named_dependency_has_a_change_case` fails if a name has no test.

`AggregateKey` adds `objective_hash` and `baseline_suite_hash` and drops `seed` and `fidelity`, which belong to the individual evaluations.

`EvaluationKey.from_manifest` takes every shared dependency from the run's frozen manifest, so a worker cannot assemble a key from live state.

### A miss has a reason, and the reason is persisted

`decide()` returns a `CacheDecision` with an outcome and a `CacheReason`, and `RunStore.lookup` writes it to `cache_decision`. "Why did this run recompute everything" is otherwise unanswerable after the fact.

Fidelity is both a key field and a separate rule. A stored `screen` result already has a different key, but on a detailed miss `decide` probes for it and reports `FIDELITY_INSUFFICIENT` with the rejected key, rather than a bare "no entry". A legacy entry reports `LEGACY_IMPORT`: found, and refused.

### Run bundles

`RunBundle.create` builds the layout architecture.md specifies and writes `manifest.json`. `copy_references` copies the source records, their blobs and the normalized records a run needs into the bundle's own store and records every one in `run_reference`. `self_check()` verifies every declared blob against its hash and every declared record against the bundle's own database, and reports what is missing instead of guessing.

`RunBundle.open` recomputes the manifest hash from `manifest.json` and compares it with the one the database recorded, so an edited manifest file is refused.

### Legacy phase output

`pob2opt/storage/legacy.py` imports `<out>/<phase>.json` files, preserves their bytes, and registers them in `legacy_import` with a note saying they have no manifest, no dependency hashes and no recorded inputs. `cache_eligible` is a read-only property returning `False`: there is no constructor argument and no assignment that makes a legacy import reusable. `reject_as_checkpoint()` guards anywhere a checkpoint path is accepted.

## Adverse cases

Exercised: a bundle whose declared blob and record are missing (reports them, does not guess); reading a payload the bundle never copied; creating a bundle where one already exists; an edited `manifest.json`; importing the same legacy file twice; a legacy file offered where a checkpoint is expected; a stored screen result offered against a detailed request.

Not tested: a corpus that is *modified* rather than deleted. The test deletes it, which is the stronger case for readability, but it does not show that a later corpus edit cannot reach back into a finished bundle. The bundle has its own database and blob store and never reopens the corpus after `copy_references`, so this is structural; it is still an untested claim.

Not tested: the cache under real evaluations. Every result here is a synthetic `EvaluationResult`; whether the dependency set is *sufficient* for PoB can only be shown once P02 produces real engine output. If P02 finds another input that changes results, `EvaluationKey` gains a field and every stored evaluation is invalidated.

## Deviations and unresolved questions

1. **`FIDELITY_INSUFFICIENT` requires an extra lookup.** On a detailed miss, `decide` performs a second lookup at screen fidelity purely to produce the better reason. It is one indexed read per miss; if that proves measurable in P08, the probe can be made optional, but the reason would then degrade to `NO_ENTRY`.
2. **`AggregateKey` excludes `seed` and `fidelity`.** architecture.md says the aggregate cache adds objective and baseline-suite hashes to the evaluation key; seed and fidelity are properties of the individual evaluations an aggregate cites, and the aggregate cites their IDs. If the reviewer reads "additionally" as strictly additive, that is a one-line change and a different aggregate identity.
3. **`copy_references` copies, it does not link.** A bundle therefore duplicates the bytes of every blob it needs. This is deliberate for readability after disconnection, and it costs disk. No deduplication across bundles exists.
