## Findings requiring correction

### G0-R01 P1 Preserve the declared Python support range

Location: [requirements-dev.txt](../../requirements-dev.txt), line 36; Python selection in [.github/workflows/offline-tests.yml](../../.github/workflows/offline-tests.yml), line 37.

The clean-install instructions say Python 3.10 or newer, both packages declare `>=3.10`, and the architecture retains 3.10. The pinned `rpds-py==2026.6.3` requires Python 3.11 or newer. A clean Python 3.10 install cannot satisfy this file. Describing 3.10 as untested does not resolve an incompatible declared dependency.

Required change: choose a dependency set compatible with 3.10, using version markers if necessary, and add Windows Python 3.10 and 3.12 checks. Do not silently raise the product's minimum Python version. If raising it is proposed, submit a concrete decision changing all affected contracts and package metadata.

Acceptance: install from scratch in isolated 3.10 and 3.12 environments, run `pip check`, offline unit/integration tests and missing-engine checks, and retain interpreter-specific dependency evidence. The current 3.12-only green run is insufficient.

### G0-R02 P1 Fail CI when pytest reports an error

Location: [.github/workflows/offline-tests.yml](../../.github/workflows/offline-tests.yml), lines 67 to 81.

The engine-skip step discards pytest's exit status with `|| true` and rejects only summaries containing `passed` or `failed`. Setup/teardown errors appear as `error`, so they evade the guard. I injected a fixture raising `RuntimeError`: pytest returned exit 1 and `34 skipped, 1 error`, while all existing guard conditions still passed.

Required change: capture and require pytest exit code 0 before checking the skip-only expectation. Prefer JUnit counts for tests/errors/failures/skips over matching console prose. Check that at least one engine case was collected and every selected case skipped for the intended missing-runtime reason. Unexpected xfails must not count as proof that everything skipped.

Acceptance: normal missing-runtime invocation passes; injected fixture error, failing test, collection error, no selected tests and interrupted pytest all fail the workflow guard. Preserve a regression test of the guard itself or a small standalone validation script.

### G0-R03 P2 Reject run paths obstructed by regular files

Location: [doctor.py](../../pob2-optimizer/pob2opt/doctor.py), lines 432 to 459; `_nearest_existing`, lines 188 to 192.

For `--run-root <existing-file>` and `--run-root <existing-file>/child`, the helper skips the file and finds a writable parent directory. The diagnostic then reports that run bundles can be written, although creating the requested directory must fail. This is a concrete false-positive in the new functionality, not a missing future feature.

Required change: inspect the requested path and every existing ancestor component. Any existing non-directory component makes the location incompatible. Keep the read-only guarantee; no need to create directories to identify this error. Describe `os.access` results as a permission indication, not a guarantee against later ACL/disk/race failures.

Acceptance: add cases for a file at the leaf, a file at an intermediate component, an existing writable directory and a valid nonexistent child directory. The first two must block `runs` and produce exit 3 in a complete diagnostic report.

### G0-R04 P2 Do not declare invalid or incompatible DLLs usable

Location: [doctor.py](../../pob2-optimizer/pob2opt/doctor.py), lines 314 to 334.

The check handles only the x86/x64 bitness pair and returns `ok` for every other detected architecture, including `unknown` and ARM64. A file containing `not a DLL` therefore passes. On this x64 process, an ARM64 PE header passes too. The checker need not load the library, but it must not assert runtime compatibility it has disproved or cannot establish.

Required change: validate a recognizable PE header and compare its machine type against the running Python process architecture. Treat unknown/truncated headers as unknown or incompatible with the engine capability blocked. Same pointer width is not enough to establish instruction-set compatibility.

Acceptance: fixtures cover malformed/truncated PE, x86 on x64, ARM64 on x64 and supported x64. Invalid/unknown cases must never report engine readiness. No DLL is loaded during the diagnostic.

### G0-R05 P2 Finish dependency locking

Location: [requirements-dev.txt](../../requirements-dev.txt), lines 25 to 37; install steps in the workflow.

The file claims transitive pinning for reproducibility but omits broad portions of the active dependency graph. Examples verified from installed metadata include `anyio`, `httpx2`, `pydantic`, `pyjwt`, `starlette`, `uvicorn`, `typing-extensions`, and pytest's `packaging` and `pygments`. Fresh installs can therefore choose different code while using the same checked-in file.

Required change: generate a complete resolved dependency lock/constraints set for the supported environments, including platform/Python-specific dependencies and package-install build requirements where needed. Install editable project packages under those constraints so the second install cannot drift the environment. Record the generation command. A hand-maintained subset is not a complete lock.

Acceptance: two clean installs for each supported interpreter resolve to the same runtime/test package versions; `pip check` passes; documentation identifies any intentionally unpinned bootstrap tooling without claiming it is locked.

### G0-R06 P2 Align future repair expectations with the specified architecture

Locations: [F10 lifecycle tests](../../tests/unit/test_f10_engine_lifecycle_contract.py), lines 70 to 97, and [F05 tests](../../tests/unit/test_f05_run_identity_and_assumptions.py), lines 124 to 159.

Several tests labelled repaired behavior assert implementation text or an API shape the spec does not require. F10 requires no `os.chdir` anywhere in `engine.py` and a timeout argument on the low-level call, whereas the architecture explicitly permits the existing cwd-dependent engine in an isolated worker with coordinator-enforced timeouts. F05 requires zero literal slices anywhere in the entire CLI and removal of old cache/default APIs, although the plan retains a legacy comparison path. A valid repair could therefore remain xfailed, and adding an unused method/parameter could make a superficial repair expectation pass.

Required change: retain source checks only as clearly scoped legacy characterization. Express repair expectations at the boundary the spec promises: unchanged parent cwd, a bounded coordinator request, terminated/replaced worker after failure, immutable new-run cache identity and configurable new-search candidate limits. Do not require deleting permitted legacy code or harmless report slices. Make migration of contradictory characterization assertions explicit.

Acceptance: tests reject a fake fix that adds a timeout parameter but never enforces it; they accept worker isolation while the worker internally changes cwd. Adding a harmless comment mentioning `catalog` or a display slice must not be treated as an optimization regression. Future P02/P08 implementations own full behavior coverage; P00 must not establish contradictory acceptance requirements.

## Smaller corrections and useful observations

1. The measurement script's warm-reset sequence omits `tree_lib.lua`, which actual `Worker.reset()` reloads. Either measure the actual operation or label it a reduced reset probe; do not call them identical. Resolve `--pob-root` to an absolute path before engine startup so later cwd changes cannot corrupt the reported path. Put checkout commit, dirty state, measurement timestamp and fixture identity in future measurement artifacts.
2. Historical baseline exclusion is appropriate, but the statement that old runs were unaffected by character auto-level mode is stronger than the evidence. The present contents of four build files do not prove their contents when unmanifested runs were made. Record “not reproduced with the currently inspected source files” instead.
3. The handoffs still say “uncommitted working tree” and use the pre-spec starting commit. Preserve that history but add a delivered-commit reference so reviewers can unambiguously tie evidence to this merged delivery.
4. Correct the “once per boot” noise description based on actual observations. Keep crash exit status visible and make large diagnostics inspectable without overwhelming ordinary output. Do not disable every native failure diagnostic merely to hide the noise.
5. The unit socket blocker applies during test execution, not module collection or subprocess execution. The current no-boot collection check inspects banners; it does not independently prove that collection cannot make network calls. Strengthen this when acquisition modules are introduced.
