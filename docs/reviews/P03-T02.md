## Required repairs

### R1 — P1: Do not forward credentials across origins

Location: `pob2-optimizer/pob2opt/acquisition/http.py:139`, redirect update at line 150 and `_request` at line 177.

The loop changes the target URL and resends the original caller headers unchanged. A redirect from approved host A to separately approved host B forwards both `Authorization` and `Cookie`. Allowing a host to supply build data does not authorize it to receive another host's credentials. The probe records both invented secrets on the second request.

Repair: compare scheme/host/effective port at every redirect; on an origin change, strip credential-bearing headers (including provider-specific ones) or refuse an authenticated redirect unless an explicit per-origin credential policy authorizes it. Scope cache validators to their representation as well. Regression: cross-origin redirects with both hosts allowed never carry A's credentials; same-origin behavior remains intentional and tested.

### R2 — P1: Reject unsafe XML before parsing, independently of encoding

Location: `acquisition/content.py:159` (`check_xml`).

The byte substring check misses UTF-16 declarations. Both a UTF-16 document containing a DOCTYPE/internal ENTITY and its compressed build code return `ok` and are persisted. ElementTree receives the unsafe document. This contradicts the explicit unsafe-XML refusal contract; no external-file disclosure was demonstrated or is claimed.

Repair: use an encoding-aware parser that forbids declarations/entities before expansion, or explicitly constrain supported encodings and reject the rest before parsing. Do not decode with ignored errors. Regression: UTF-8 and UTF-16 DOCTYPE/entity cases, direct and compressed, return typed `invalid_response`, create no SourceDocument/blob, while ordinary supported XML still imports.

### R3 — P2: Keep cache identity separate from display redaction

Location: `acquisition/state.py:106` and `service.py:289`.

`?variant=first` and `?variant=second` become the same redacted key. After caching the first resource with ETag `v1`, the second request incorrectly sends its validator; a 304 returns the first SourceDocument with status `ok`. ETags are scoped to a selected representation, not globally unique across URLs. This can silently substitute another build. Authorization headers also do not partition this cache.

Repair: use a secret-safe, collision-resistant key for the actual request identity, including relevant non-secret representation selectors; disable shared caching for authenticated input unless an explicit credential/representation partition is available. Never persist plaintext credentials as a fix. Regression: different redacted query values and distinct auth contexts do not share validators/documents; repeated identical public inputs still reuse the cache.

### R4 — P2: Close real transport responses without requiring body iteration

Location: `acquisition/transport.py:54`, `:107`, `:112`.

`Response.close()` only closes `_guarded_chunks`. Closing an unstarted Python generator does not enter its `finally`, so a 403 response remains open. The same pattern affects redirects, 304, other discarded statuses and Content-Length rejection. The current test double's close method masks the real transport's behavior.

Repair: give the response wrapper explicit ownership of the underlying response and an idempotent close path independent of iteration. Regression: inject a fake requests session into RequestsTransport and assert raw response closure on each early-return path and on partial-read failure. No real socket is needed for these tests.

### R5 — P2: Preserve cooldown across requests to the same provider

Location: `acquisition/http.py:160`; `scheduling.py:116`.

After a 429 with Retry-After 120, the outcome gives a deferral at 00:02, but fetching another URL for the same provider sends immediately at 00:00. The scheduler remembers only the last-request time, not the provider's retry deadline. A crawl can violate the advertised cooldown simply by moving to its next page.

Repair: retain a provider not-before deadline and enforce it before every send, including new URLs and a fetch that exhausted its final attempt. Return a deferral for long waits rather than blocking the coordinator. Regression: with an injected clock, the second URL cannot reach the transport before the full 120 seconds; another provider remains independently usable. Resume must preserve or conservatively honor a pending deadline.

### R6 — P2: Resolve redirected 304 responses using the cached request identity

Location: `acquisition/service.py:313`, `:339`.

The first A-to-B redirect stores cache state under A. On the repeat request, B returns 304 but `_unchanged` looks up B. The document is present, yet the operation returns `invalid_response` claiming the corpus no longer holds it.

Repair: carry the original cache key through fetch/304 handling, with explicit redirect/representation binding. Do not blindly forward a validator to a newly changed destination. Regression: A→B→200 followed by A→B→304 returns the original document, one blob, two attempt records; changing A's redirect target does not reuse B's cached representation.

### R7 — P2: Apply path policy to the URL that will actually be sent

Location: `acquisition/hosts.py:129`.

A rule allowing `/approved/` accepts `/approved/../blocked`. Requests prepares it as `/blocked`. The policy and transport therefore disagree about the path being approved. The probe uses `requests.Request.prepare()` without making a request.

Repair: canonicalize consistently before both approval and sending, or refuse ambiguous dot-segment/encoded forms. Regression: direct and redirect dot-segment URLs cannot leave the approved path; a normal allowed URL still works. Validate the prepared request destination, not merely the original spelling.

### R8 — P2: Turn JSON depth exhaustion into a typed refusal on Python 3.10

Location: `acquisition/content.py:142`.

A 4,001-byte JSON value nested 2,000 levels raises an uncaught `RecursionError` on Python 3.10.22; Python 3.12.4 accepts it. `_check_json` catches ValueError only. A small input can escape the promised typed-failure boundary on a supported interpreter.

Repair: define a supported nesting bound and enforce it consistently, converting excessive depth/parser exhaustion to `MalformedContent`. Regression: run this input through service and CLI on both interpreters, with structured failure and no successful document; ordinary JSON still works.

## Reassessment and disposition

P03-T02 is not ready to merge. Fix R1–R8 and add behavioral regression tests, including the actual RequestsTransport seam. Existing green tests do not cover these cases. No provider adapter should depend on this implementation being accepted until re-review.

These findings do not reopen previously accepted P01/P02 work; the defects are in the new acquisition layer. After repair, re-run the focused suite on both interpreters and the offline unit/integration suite. Remove the unrelated `.review-pr5-engine.txt` and `docs/evidence/PR-5/repairs.patch` from PR6 unless deliberately justified; that is a low-priority scope cleanup, not a ninth blocker.
