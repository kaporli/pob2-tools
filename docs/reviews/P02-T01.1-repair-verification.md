## Disposition

| Finding | Repair and acceptance evidence |
|---|---|
| R1: fast replies evade hard memory limit | Check ready/reply frames, requests and operation boundaries, including cached identity reads. A real synthetic worker allocating 200 MiB and replying before the polling interval now raises `EngineMemoryLimit`; startup and nonfatal error replies are also covered. Keep periodic checks during active requests and slow shutdown. |
| R2: fatal errors evade exhaustion; startup losses disappear | Retain the spawned handle and PID before waiting for ready. Count every unplanned fatal loss once, regardless of error type; preserve the original typed exception. Record history immediately and idempotently. Startup exceptions, fatal handlers, startup timeouts and startup memory kills exhaust the budget. Live nonfatal errors and planned recycling do not consume it. Only a complete successful operation resets it. |
| R3: missing memory readings fail open | A live worker with an unreadable probe under either memory bound is terminated with `EngineMemoryProbeError`, stored as `engine_crash`. Clear the latest reading, retain the historical peak, and count the loss. Startup, wait, reply and reuse cases cover hard and soft bounds. A dead process remains a crash; explicit unbounded execution and normal shutdown remain supported. |

No automatic request retry was added. Sampling can overshoot between reads;
this is not an OS allocation ceiling or an idle background watchdog.
