## Method

A field name settles nothing. `TotalDPS` does not say whether it counts
projectile overlap, and `CombinedDPS` does not say what unit it is in. Each
semantic below was settled by a pair of complete build documents differing in
exactly one declared way, both evaluated through the same adapter, or it is
recorded as a gap.

The thirteen fixtures, all level 60 with a `-30` resistance penalty:

| Fixture | What it is | Pairs with |
|---|---|---|
| `baseline` | crafted rare bow, Lightning Arrow at quality 20 | `accuracy`, `projectiles` |
| `accuracy` | the same, weapon carrying `+2000 to Accuracy Rating` | `baseline` |
| `projectiles` | the same, weapon carrying `Bow Attacks fire 2 additional Arrows` | `baseline` |
| `dot` | Contagion alone | `dot_longer` |
| `dot_longer` | Contagion plus Prolonged Duration II | `dot` |
| `cast_direct` | Fireball cast directly | `cast_wrapped` |
| `cast_wrapped` | Fireball socketed inside Cast on Critical, main skill 2 | `cast_direct` |
| `cast_wrapped_<meta>` | the same for Cast on Block, Cast on Dodge, Cast on Minion Death and Cast on Elemental Ailment | `cast_direct` |
| `cooldown` | Frost Bomb, a skill with a declared cooldown | none |
| `show_average` | Incinerate, a skill whose data sets `showAverage` | `baseline` |

The weapon rolls and the `+2000` are invented. They exist to move one quantity.

## What the fixtures established

### F-DPS. `TotalDPS` is `AverageDamage` multiplied by `Speed`

`baseline`: `AverageDamage` 15.88359375, `Speed` 1.26, product
20.013328124999997, `TotalDPS` 20.013328125. The two are not independent
measurements and must not be combined.

### F-ACC. Damage per use already contains hit probability and critical strikes

| | `baseline` | `accuracy` |
|---|---|---|
| `HitChance` | 25 | 100 |
| `CritChance` | 1.25 | 5 |
| `AverageDamage` | 15.88359375 | 65.8875 |

Hit chance quadrupled; damage moved by 4.148, not 4. PoB reports the crit
chance after the hit roll, so it moved with it, and the damage followed both:
`1.05 / 0.253125 = 4.1481`. Multiplying `AverageDamage` by `HitChance`
downstream counts the hit roll twice.

### F-PROJ. Projectile overlap is not included

| | `baseline` | `projectiles` |
|---|---|---|
| `ProjectileCount` | 1 | 3 |
| `AverageDamage` | 15.88359375 | 15.88359375 |
| `TotalDPS` | 20.013328125 | 20.013328125 |

Identical to the last digit. PoB calculates one projectile against one
configured enemy. PoB does ship per-skill overlap configuration variables
(`ShrapnelBallistaProjectileOverlap`, `toxicRainPodOverlap`,
`stormRainBeamOverlap`, `perforateSpikeOverlap`), but each is gated on an
`ifSkill` naming a skill that does not exist in the pinned PoE 2 catalog, so
none of them applies to any gem this system can propose. How many projectiles
reach a target is therefore P07's, and it is declared as the gap
`projectile_overlap_multiplier`.

### F-DOT. Damage over time is a rate, and duration does not change it

| | `dot` | `dot_longer` |
|---|---|---|
| `Duration` | 5.016 | 6.765 |
| `TotalDot` | 38.033333333333 | 38.033333333333 |
| `TotalDotDPS` | 38.033333333333 | 38.033333333333 |
| `CombinedDPS` | 38.033333333333 | 38.033333333333 |

The only difference is a duration support. The reported number is damage per
second while the effect is active, and nothing in it accounts for the total
damage of one application or for the cost of reapplying it. Ailment damage
over time is different in one respect: PoB folds ailment chance and stack
potential into the rate (`IgniteStackPotential` is ailment chance times use
rate times ailment duration), so for ailments the duration does enter, as
uptime. The reapplication cost of a skill-duration effect is declared as the
gap `dot_reapplication_cost_s`.

### F-TRIG. A meta gem does not change the socketed spell's cadence

| | `cast_direct` | `cast_wrapped` |
|---|---|---|
| main skill reported by the engine | Fireball | Fireball |
| `Speed` | 0.83333333333333 | 0.83333333333333 |
| `Time` | 1.2 | 1.2 |
| `AverageDamage` | 69.55 | 69.55 |
| `TotalDPS` | 57.958333333333 | 57.958333333333 |

PoB does model trigger cadence when the skill data declares it:
`CalcOffence.lua` sets `output.Speed = skillData.triggerRate` for a skill with
`triggered` and a `triggerRate`, or derives the rate from `triggerTime`. In
the pinned PoE 2 catalog no meta gem produced that state. All five that can
wrap a spell (Cast on Critical, Cast on Block, Cast on Dodge, Cast on Minion
Death, Cast on Elemental Ailment) returned `Speed` 0.83333333333333,
`AverageDamage` 69.55 and `TotalDPS` 57.958333333333 with `Fireball` as the
reported main skill: the same numbers as casting it directly, to the last
digit. Trigger cadence is declared as the gap `trigger_rate_per_second`.

### F-CD. A cooldown becomes the use rate

`cooldown` (Frost Bomb): `Cooldown` 6.006, `Speed` 0.16650016650017 = 1/6.006,
`Time` 6.006, `AverageDamage` 88.14, `TotalDPS` 14.675324675325. The engine
assumes the skill is used exactly on cooldown and the cast time disappears
into it. A skill without a cooldown reports no `Cooldown` key at all, which is
a gap and not a zero: a zero cooldown would mean an unbounded use rate.

### F-UNIT. `CombinedDPS` changes unit with the skill

`show_average` (Incinerate), `skillData.showAverage` true:

| Key | Value |
|---|---|
| `AverageDamage` | 23.32 |
| `CombinedDPS` | 23.32 |
| `Speed` | 4 |
| `TotalDPS` | 93.28 |
| `FullDPS` | 105.6560583877 |

`CalcOffence.lua` line 6265 writes `AverageDamage` into `CombinedDPS` when the
skill data sets `showAverage` and `TotalDPS` otherwise. The same key is
therefore damage per use for some skills and damage per second for the rest,
and the two differ by the use rate, here a factor of four. `baseline` has the
flag false and `CombinedDPS` equal to `TotalDPS`.

This is reported, not guessed: `buildSummary` in `pob2-mcp/pob2mcp/bootstrap.lua`
now returns `mainSkillShowAverage`, `LoadedBuild` carries it, and
`combined_damage` is declared `conditional` so a snapshot that does not carry
the flag supplies no value at all.

### F-FULL. `FullDPS` aggregates groups and includes damage over time

`show_average`: `TotalDPS` 93.28 plus `TotalDotDPS` 12.376058387699 equals
`FullDPS` 105.6560583877. `FullDPS` sums the socket groups flagged
`includeInFullDPS`, so it is the only per-second number that is comparable
across skills whatever their `showAverage` flag.

### F-COST. Cost has two units and both are reported

`baseline`: `ManaCost` 25 per use, `Speed` 1.26, `ManaPerSecondCost` 31.5. The
per-second figure is the per-use one times the rate, so the two must not be
added. PoB reports the cost of using the skill and no sustainability model.

### F-AREA. The radius carries PoB's own metre conversion

`baseline`: `AreaOfEffectRadius` 32, `AreaOfEffectRadiusMetres` 3.2. The raw
radius is in PoB area units, ten per metre, and the metre figure is PoB's own
conversion rather than an assumption of ours. `contracts.md` requires exactly
this: a distance carries a declared unit and its conversion evidence.

### F-DEF. Defences

`baseline`: `Life` 65, `EnergyShield` 0, `Mana` 50, `Spirit` 100,
`SpiritUnreserved` 100, `Armour` 0, `Evasion` 7, `FireResist` -20,
`TotalEHP` 56.354679802955, `PhysicalMaximumHitTaken` 65, `BlockChance` 0,
`EffectiveMovementSpeedMod` 1. These are a level 60 character with no tree and
one weapon; the point is that each output exists and is named, not that the
values describe a build anyone would play. `TotalEHP` depends on the incoming
damage composition PoB assumes and is not a survival result for any encounter.

## The declared inventory

Owner `pob` means the pinned engine computes it and nothing downstream may
recompute it. Owner `simulator` means P07 computes it and the engine supplies
nothing. Each primitive has exactly one owner and one unit.

### Damage per hit or use

| Primitive | Native key | Unit | Owner | Includes | Excludes |
|---|---|---|---|---|---|
| `damage_per_use` | `AverageDamage` | damage per use | pob | hit probability, crit, enemy resistances at the configured enemy level | damage over time, ailments, projectile overlap, other groups, rotation and setup time |
| `hit_damage_per_second` | `TotalDPS` | damage per second | pob | the above and the use rate | the same, plus trigger cadence unless the skill declares one |
| `combined_damage` | `CombinedDPS` | damage per second, or damage per use when the skill declares `showAverage` | pob | hit damage, damage over time when the unit is per second, culling and reservation multipliers | other groups |
| `aggregate_damage_per_second` | `FullDPS` | damage per second | pob | every group flagged `includeInFullDPS`, damage over time | projectile overlap, rotation and setup time |

## Gaps

Each is a `DataGap` of the stated kind, produced by
`PrimitiveSnapshot.gaps()` rather than filled with a constant.

| Gap | Kind | Why | What would close it |
|---|---|---|---|
| `projectile_overlap_multiplier` | unsupported_rule | F-PROJ: extra projectiles change nothing, and PoB's overlap configs name no PoE 2 skill | an encounter model with positions, or a reviewed engine extension |
| `targets_hit_per_use` | unsupported_rule | PoB calculates against one configured enemy | the same |
| `trigger_rate_per_second` | unsupported_rule | F-TRIG: no meta gem in the pinned catalog marks the socketed spell triggered | source evidence for each meta gem's trigger rule, then a rule with one owner |
| `dot_reapplication_cost_s` | unsupported_rule | F-DOT: the rate ignores duration, so nothing charges for reapplication | an encounter model that schedules the reapplication |
| `sustained_damage_per_second` | unsupported_rule | no native output | P07 |
| `setup_time_s` | unsupported_rule | no native output | P07 |
| `cooldown_s` on a skill with no cooldown | missing_input | the key is absent | nothing: absence is the correct answer, and zero would mean an unbounded rate |
| `combined_damage` without the `showAverage` flag | missing_input | F-UNIT: the unit is undecidable | the engine flag, which `buildSummary` now reports |

## What was not established

* **Whether PoB's numbers match the game.** Nothing here is a gameplay
  measurement, and no amount of engine agreement becomes one. P09 owns that.
* **Whether a meta gem has a real trigger cadence in PoE 2.** F-TRIG shows
  only that the pinned catalog does not declare one. That is a statement about
  the data, not about the game; the rule needs sourced evidence and belongs to
  P06.
* **Ailment damage over time beyond the mechanism.** `IgniteDPS` visibly folds
  ailment chance and stack potential into the rate, which is recorded above,
  but no fixture pair isolates each factor.
* **Minion outputs.** `minion.output.CombinedDPS` is read by the legacy
  `OPT_minion_dps` helper and is not in this inventory. No primitive P07 uses
  depends on it yet, and inventing a declaration without a fixture is the
  failure this task exists to prevent.
* **Weapon-set and secondary-hand outputs.** Not exercised by any fixture
  here.
